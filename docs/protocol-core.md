# 协议基础模块

## 配置与日志

采用已确认的 cJSON 和 EasyLogger。配置解析拒绝未知键、重复键、非法类型、不可表示的物理值及不完整 JSON。
文件不超过 64 KiB，JSON 嵌套不超过 32 层。角色和版本必须明确提供；其余字段使用显式默认值。
参数单位由键名给出：`_mv` 毫伏、`_ma` 毫安、`_mah` 毫安时、`_wh` 瓦时、`_degc` 摄氏度、`_ms` 毫秒。
充电电流配置为正的幅值，线上按负电流和 −400 A 偏移编码。

日志由协议线程格式化并写入 EasyLogger 的 64 KiB 异步环形缓冲区，平台独立线程负责控制台和文件 I/O。EasyLogger 自有配置位于 `app/logging/`；
文件所有权及实际 I/O 位于 `backends/support/<平台>/log_sink.c`。
默认开启文件保存，未指定路径时按上海时间（UTC+8）生成 logs/YYYYMMDD_HHMMSS_role.log，独占创建避免覆盖。显式 log_path 继续支持指定路径。
文件开启失败、异步缓冲满、写入失败和关闭失败均导致非零退出；退出前排空缓冲并等待工作线程结束，关闭文件输出时不创建文件。

Linux 初始化阶段通过 `log_retention` 按角色各保留最近 3 次自动记录。应用向契约传入已创建的自动路径，不传显式路径；后端用归属标记区分会话、文件锁保护活动记录，整组清理应用日志及自动抓包。显式复用的旧日志退出自动管理。文件访问封装于 Linux 后端，Zephyr 文件保留操作返回 ENOSYS。

`sim_build_info` 保存构建时生成的只读软件版本、UTC 构建时间、目标及编译器信息，运行时不访问 Git。Linux `--version` 在加载配置前退出。`sim_config_snapshot` 使用 cJSON 序列化校验后的有效配置，通过回调输出不超过 512 字节的 JSON 片段，所有分配和回调错误均传播；调用期间拥有并释放临时对象。

启动详情使用保留的 `DETAIL` 标签，经 EasyLogger 原生异步环形缓冲输出。Linux 文件后端按行识别标签，处理跨任意缓冲边界的记录，文件保留全部内容、控制台省略详情；普通运行记录维持原输出策略。`sim_log_detail` 用于初始化和独立工作线程的会话配置证据，必要时对生产速度施加有限等待，不得用于协议收发或周期调度。

## 报文接口

命名统一使用 `gbt27930`：文件、函数及类型采用小写前缀，宏及枚举成员采用 `GBT27930`。
原 `gb27930` 接口已同步更名，调用方需更新头文件路径和标识符；报文格式与运行行为不变。

`gbt27930_codec` 显式读写字节及位，不使用结构体映射或主机字节序。
公开接口包括描述符查询、字段查询、物理值设置、负载编码及解码。
字段具有范围、默认值和精确分辨率；不可精确表示的配置拒绝窄化。
可选字段未提供时，解码结果通过 `available` 标明，不用默认值伪造接收数据。

当前表项为 CHM、BHM、CRM、BRM、BCP、CTS、CML、BRO、CRO、BCL、BCS、CCS、BSM、BMV、BMT、BSP、BST、CST、BSD、CSD、BEM、CEM。
本地整理稿称“23 种”，但逐项表格列出上述 22 种；实现按明确列出的报文，不臆造额外一种。
BRM 按已记录的勘误使用 49 字节；CCS 发送长度分别为 2015 的 8 字节、2023 的 7 字节。
CTS 使用可配置的 BCD 日期时间。可选单体电压、温度和预留数据使用有界数组。

## TP 适配

`j1939_tp` 将上游内部结构封装在不透明实例中，公开创建、完整负载发送、帧输入、周期推进、状态查询和重置。
所有内存在创建时分配；负载复制进入实例缓冲区，接收回调内的数据只在回调期间有效。
一次调用最多发送一个 DT 包，使用传入的单调毫秒时间，不阻塞等待。支持 9～1785 字节。

上游原样保留，继续负责 CM/DT 编码及接收存储。外层执行源/目的地址、DLC、长度与包数关系、序号、会话和 PGN 校验，
在上游缓冲区写入前拒绝非法数据。通用完成通知绕开上游内置应用 PGN 分发，不调用原始全栈 listener。
TX/RX 使用独立上游上下文；每个实例只对接一个配置对端。库的全局回调限制所有实例必须串行、不可嵌套调用。

发送 RTS 沿用上游的单包 CTS 窗口；接收窗口可配置，受对端 RTS 最大包数限制。
按等待状态分别执行 T1、T2、T3、T4；支持 CTS Hold、请求已发送包重发、Abort 和提前 ACK 忽略。
计时采用无符号差值处理回绕。BAM 和其他 J1939 应用层功能不在 GB/T 27930 适配范围内。
下层发送错误由外层保存并通过事件和返回值传播，不依赖上游无条件成功的 void 发送回调。

## 报文启停与模拟条件

发送调度按整理稿新增的 2015 附录 D、2023 附录 B 启停条件判断，跨阶段仍有效的报文继续保持周期。BRO 必须实际发送 AA 且收到 CRO AA 后停止；本地就绪条件成立但报文被丢弃时不能提前进入充电。

2015 CCS 等到 BCL 和 BCS 均收到后启动；2023 CCS 在收到 BCL 后启动，CRO 仍等到两者均收到才停止。CST 持续到 BSD，CSD 收到 BSD 后才启动。桩主动中止时，BMS 在 2015 回复一帧 BST 后发送 BSD，2023 回复五帧后发送 BSD；计数以实际发送成功为准。2015 整理稿 BST 停止条件的括注存在重复表述，这里按“收到 CST 后回复 BST，再开始 BSD”的事件顺序实现，后续应以原标准及实物核对。

2015 BSD 收到 CSD 后继续发送，直到收到新 CRM 或模拟辅助电源关闭；两版 CSD 持续到模拟断电或允许的新会话。2023 BSD 收到 CSD 后停止。默认统计完成 1000 ms 后自动提供模拟断电事件；关闭 `auto_aux_power_off` 后可用场景 `aux_power_off` 提供条件，否则仍受会话时限约束。进入统计完成状态本身不会立即伪造断电条件。

2023 BMS 在首次 CML 后、尚未实际发送 BRO AA 时，可通过 BCP 字段的 `set_parameter` 事件请求参数更新；至少完成两次更新 BCP 的 TP 传输，再发送 BRO 00 并重新等待就绪。2015 错误报文保持到新 CRM 或模拟断电，2023 保持到该轮超时处理结束；旧会话的错误报文不会反复打断恢复握手。

## 验证

`test_sim_core` 使用独立 BCL、BCP、CTS 字节向量，检查两版长度、配置拒绝路径、1785 字节 TP 传输、10 ms 调度下限、
T1～T4、时钟回绕、序号 0、截断帧、会话冲突、提前 ACK 及发送失败。
该测试无需 CAN 或真实等待。完整应用的 vcan 与实物验证另外执行；不声明完整 MISRA 或协议认证。

`test_message_lifecycle` 以一个协议引擎对接独立脚本化对端，用可控时间检查双版本 BRO/CCS/CST/BST/BSD/CSD、错误报文跨恢复周期、模拟断电和两次 BCP 更新边界，避免只依赖两个相同实现互通。正常 vcan 场景另外检查原始收发日志中的关键报文先后关系及 BST 次数。

## 可重复会话调度

`sim_session` 在终端/UI 输入与单次协议引擎之间管理生命周期：start 创建新引擎，receive/tick 使用相对本轮起点的协议毫秒，返回完成或失败后销毁引擎并保留空闲对象。手动桩端由主循环的 Enter 事件调用 start；手动 BMS 由合法对端 CHM 启动。CAN、日志和抓包资源仍归主循环所有，跨充电轮次保留。自动模式复用同一接口，但只运行一轮。`sim_session_io_error` 保留当前轮首次底层发送错误，供主循环区分资源故障与可回到待机的协议异常。

## 阶段证据快照

`sim_transition_t` 按每次阶段进入保存有界证据，不从日志解析 UI 状态。阶段迁移先关闭旧记录，再创建新记录；超时触发点先记录实际计时原点、阈值和等待时长，再记录失败、迁移到恢复阶段。已通过角色、阶段及编解码检查的有效负载才更新接收证据。重试清除接收计时器，不清除上一尝试的已冻结阶段记录。

注入器通过可选同步 `sim_fault_observe` 回调，在执行命中动作前记录证据；回调只复制到当前阶段记录，不操作 UI、文件或协议。阶段内分开累计配置与手动命中数，只保存最后一次命中的详细参数。

会话结束前调用 `sim_engine_finish` 冻结最终记录，再复制快照并释放引擎；它只处理观测信息，不发送报文或推进协议。UI 继续通过原有非阻塞桥读取值副本。结构扩展适用于无 UI 的 Linux 构建，Zephyr 保留原有骨架边界。
