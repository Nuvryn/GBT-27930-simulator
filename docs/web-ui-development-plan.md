# LVGL Web 屏幕镜像开发计划

## 目标与首版范围

同一套 LVGL 页面通过配置选择实体屏幕或 Web 镜像。Web 模式在板端内存中绘制，无需实体屏幕、触摸设备或 `/dev/fb0`，PC 浏览器显示画面并回传指针操作。协议、配置编辑、错误注入和阶段详情继续复用现有实现。

- 首版实体屏幕与 Web 二选一，单个浏览器客户端；不实现同时输出或多客户端协同控制。
- Web 使用固定虚拟画布尺寸，浏览器等比例显示并转换点击坐标。实体屏幕仍读取系统尺寸，不添加强制分辨率配置。
- 支持点击、拖动、松开、断线重连。浏览器断开释放指针按下状态，协议继续运行；重新连接获取完整当前画面。
- 浏览器资源随程序提供，保持可执行文件加配置文件的部署方式，不要求板端安装 Python、Node.js、桌面环境或访问互联网。
- ARM Linux 为运行目标，Zephyr 仍只保留关闭 UI 的骨架。本轮不开发 BSP。

## 依赖选型状态

已选定 LibVNCServer 0.9.15（板端 C，GPL-2.0-or-later）与 noVNC 1.7.0（浏览器客户端，主要为 MPL-2.0，附带组件许可证须保留）。LibVNCServer 提供 VNC/WebSocket 协议处理，noVNC 提供浏览器画面和指针交互。

适配成本中等：新增内存显示后端、线程间画面和输入交换、静态网页资源打包、构建裁剪及退出清理。已采用内嵌资源和两个监听端口，关闭可选压缩与 TLS 构建依赖；不承诺未经板端验证的性能指标。

**用户已确认采用这组依赖。** 已按官方标签和提交哈希固定，构建不自动下载依赖；具体哈希见 dependencies.md。

来源：

- [LibVNCServer](https://github.com/LibVNC/libvncserver)
- [noVNC](https://github.com/novnc/noVNC)

## 配置与兼容

增加 `ui.backend`，取值 `fbdev`、`web`，缺省为 `fbdev`。保留现有 `ui.enabled`、实体显示与触摸设备配置；关闭 UI 的原有启动方式继续有效。

`ui.web` 提供监听地址、网页访问端口、固定画布宽高及画面发送频率上限。使用独立 VNC/WebSocket 端口，最终配置与用法见 ui_usage.md。Web 模式不要求 `input_device`；实体模式仍要求有效输入设备。尺寸、端口、后端名及资源初始化失败均明确报错，返回非零，不静默切换后端。

有效配置快照、保存回读及每轮会话证据需包含新增配置。补充独立的 Web 桩端/BMS 示例，原实体 UI 配置无需改动。

## 模块边界与线程

- 应用仅传递显示后端选项，不包含网络库或操作系统头文件。
- Linux 后端选择 fbdev/evdev 或内存画面/Web；公共契约保持平台无关，不在应用内增加平台条件分支。
- LVGL 对象和输入设备由 UI 线程独占。网络线程接收事件后通过有界通道交给 UI，不能从网络回调直接操作 LVGL。
- 画面通过受保护的缓冲区交换，发送慢时合并待更新区域并保留最新画面，不能无限排队或阻塞协议线程。
- 指针按下/抬起顺序必须保留，队列压力或连接丢失时保证最终释放，不能留下按住不放的状态。
- 会话控制继续经过现有 `sim_control` 通道；断网不自动停止充电，网络处理不进入协议线程。
- 退出时停止网络处理、关闭客户端及监听端口，清理显示缓冲和网页资源，再销毁 LVGL；端口占用、内存分配失败等均可观察。

## 实施与验收

1. 确认依赖，固定源码、哈希和许可证，验证 Linux/ARM 可裁剪构建及网页资源部署方式。
2. 增加配置及显示后端选择，验证旧配置、无 UI、实体模式和 Zephyr 骨架兼容。
3. 接入内存绘制和浏览器镜像，验证缺少显示/输入设备时 Web 模式可启动并显示中文页面。
4. 接入指针事件、单客户端和重连，验证真实浏览器打开页面、点击按钮、拖动滚动、断开后释放指针以及重连完整画面。
5. 使用真实 CAN 接口的 vcan 双进程，覆盖 2015/2023、两种角色及多轮会话，验证网页控制、参数保存、注入和失败详情；网络断开不影响协议调度。
6. 检查占用端口、非法配置、慢客户端和退出资源清理；执行 Linux 回归、ARM 两种 UI 构建及 Zephyr 关闭 UI 骨架检查。

浏览器交互和网络行为需要实际测试，不以截图、编译成功或客户端握手代替。i.MX6ULL 的 CPU 占用、网络带宽和操作延迟留待板端测试；缺少板子不判为通过。既有 CAN 关闭生命周期泄漏继续单列，不能屏蔽或混淆为 Web 验证通过。
