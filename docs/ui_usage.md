# LVGL 触屏界面

界面采用简体中文，内嵌思源黑体 16 px 字形子集，部署不需要额外字体文件。协议报文名、配置键、错误标识及原始日志保留英文，方便检索；键盘支持数字和英文，不含中文输入法。字体覆盖界面固定文案，不保证覆盖任意配置字符串。

## 构建和启动

LVGL 固定为 v9.6.0（`80ca777e37a2b176770726a02e07a6fb79ef0b39`），源码随仓库保存，构建不访问网络。使用 C-only 构建、软件渲染和需要的控件，不依赖 SDL、Qt、tslib、GPU 或显示服务器。

```bash
# Linux / WSL：启用 UI
cmake -G Ninja -DPLATFORM=linux -DSIM_UI=ON -S . -B build-ui
cmake --build build-ui -j
./build-ui/gbt27930_simulator --config config/charger_ui.json

# ARM Linux：使用相同 UI 源码交叉编译
cmake -G Ninja -DPLATFORM=linux -DSIM_UI=ON -DBUILD_TESTING=OFF \
  -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/arm-linux-gnueabihf.cmake -S . -B build-armhf-ui
cmake --build build-armhf-ui -j
```

默认 `SIM_UI=OFF`，不编译或链接 LVGL。Zephyr 本轮仅支持 OFF 骨架编译；ON 会在配置阶段明确报错。每个构建目录继续导出 compile_commands.json。

运行开关独立于构建开关，配置示例：

```json
{
  "role": "charger",
  "version": 2015,
  "start_mode": "manual",
  "can_interface": "can0",
  "file_log": true,
  "ui": {
    "enabled": true,
    "framebuffer": "/dev/fb0",
    "input_device": "/dev/input/event1",
    "rotation": 0
  }
}
```

BMS 示例见 config/bms_ui.json；两个示例中的触摸路径都是占位示例，应替换为实际可用的输入设备。支持 2015/2023 A 类，version 可按需修改。

| ui 字段 | 默认值 | 说明 |
|---|---|---|
| enabled | false | 启用时必须使用 manual 模式及含 UI 的可执行文件 |
| framebuffer | /dev/fb0 | 非空，最多 255 字节，使用官方 fbdev 后端 |
| input_device | 空 | 最多 255 字节；fbdev 启用时必须明确指定 evdev 设备 |
| rotation | 0 | 0/90/180/270 度，显示及指针坐标经 LVGL 处理 |

**实体 fbdev 的分辨率、像素格式和行跨度来自系统显示设备，不在 config 中配置。** 800×480 只是设计参考，布局依实际宽高换行、滚动；不缩放或覆盖系统分辨率。软件测试覆盖 800×480 和 480×272。未实现任意尺寸屏幕保证、热插拔换屏或在应用内修改显示时序，也不涉及 BSP 开发。

UI 关闭时不打开显示/触摸设备，保留 Enter 及 auto 运行方式。UI 启用时不读取 stdin，因此可以没有控制台输入；桩端通过屏幕 Start 开始。请求启用却未编译 UI、配置非法或设备初始化失败均返回非零，不静默回退。初始化成功后才输出 READY。

## 页面和操作

- **主页**：角色/版本/CAN、会话编号、阶段/会话时间、参数修订号；流程节点分别显示 未进入、当前、已进入、异常。另显示按实际事件顺序排列的路径、正在等待/监控的报文和就绪条件、最近错误及其报文。状态来自结构化协议快照，不解析日志或播放固定动画。节点与路径回到 Idle 后保留，下一轮重新开始；恢复和重复阶段按实际进入顺序显示。超过 64 次迁移明确提示旧历史被淘汰，文本路径展示最近 12 次。
- **参数设置**：仅编辑本角色的标量字段，按报文注册顺序排列，显示范围和步长。V/A 精确转换为 mV/mA 整数，不使用浮点舍入接受非法值。其他单位见字段键；枚举及跨字段约束仍通过原校验器。单体数组及字符串等复杂字段继续由 JSON 提供。
- **充电控制**：桩端 开始充电 触发 CHM；BMS 无本地主动开始，等待合法对端 CHM。停止充电 通过独立通道请求当前会话正常中止，不被普通命令队列挤占；过期会话请求不会停止另一轮。正常或异常处理结束后继续待机。Ctrl-C/SIGTERM 保留现有中止/退出语义。
- **错误注入**：选择阶段、报文、tx/rx、动作、次数、持续时间、延迟、字节及替换值，Enable/Disable 控制一条临时手动规则。支持 drop/delay/duplicate/corrupt/length/id；TP_DT 的字节 0 是序号。替换值使用十进制。待机可预置下一轮规则，顶部显示 ARMED；运行中显示 ACTIVE 及命中次数。次数/持续时间耗尽显示 OFF。
- **日志信息**：版本、构建时间、目标、配置来源和日志/抓包开关；日志可滚动、暂停显示、按标签或文本筛选、清空显示。文字键盘与数字键盘按输入框切换，完成/取消收起键盘。

主页的本端数据标为 本端模拟；对端数据标为 对端上报，仅在相关报文已合法接收且未过期时显示。失效或未收到的数据标为 未收到或已过期，不能当作采集值。硬件动作日志仍仅代表模拟动作；控制台和文件日志沿用英文，运行期动作日志仍为英文，测试中的暂停/恢复证据同步使用英文。

## 流程节点详情

主页的每个流程节点都可点击，弹出详情窗口；异常节点标红，默认选中该阶段最近一次保留的失败记录。窗口通过下拉框选择同一阶段的每次进入记录，记录编号为本轮的全局进入顺序，不合并不同重试的证据。关闭窗口返回原页面，详情窗口显示期间阻止操作底层页面。

详情包括进入/退出时刻、进入/退出原因、停留时长、本阶段最后一条有效接收报文及其时刻。所有时刻采用相对本轮会话开始的单调毫秒时间。进行中的阶段持续更新，退出后冻结时长；会话结束回到待机后仍可查看，新会话开始清除旧历史并关闭旧详情。

失败记录保存中文说明及原始错误标识、失败时刻和相关报文。接收超时同时保存实际用于判断的首次等待/持续接收/阶段等待类型、计时起点、阈值、实际等待时长，以及失败时计时器保留的相关报文最后一次有效接收时刻。会话时长超限使用会话起点。无效帧、错误阶段报文及被注入丢弃的报文不算有效接收；非超时失败不推测超时阈值，缺失证据显示“未记录”。运行资源错误的具体返回代码结合主页会话结果和日志查看。

每条阶段记录分别累计本端配置/手动注入命中次数，并保存最近一次命中的来源、规则编号（从 0 开始）、方向、报文、动作、时刻及对应延迟或修改参数。取消规则不删除既有命中证据。仅保留最近一次命中的详细参数，其余查看文件日志；命中与失败只表示关联，不自动断言因果，也无法推断对端注入或未发送原因。

历史仍为最多 64 条阶段进入记录。超过上限时明确提示淘汰；当前查看的记录被淘汰后，不自动替换成其他记录，需要重新选择。保留历史中没有某阶段时，区分“本轮尚未进入”和“较早历史已淘汰，无法判断”，不把证据缺失当作未发生。

## 参数、生效和保存

启动配置是初始值。待机编辑后点击 应用到下一轮，由协议线程校验并替换下一轮参数，成功后增加修订号；充电时编辑禁用，Apply 请求也会在协议层拒绝。BMS 自动启动使用最近一次已确认 Apply 的值，未提交输入不影响协议。

每轮引擎复制参数。运行中改变报文统一使用错误注入，不直接修改本轮配置。控制请求带编号并给出结果；队列容量为 8，满或短时繁忙提示 Busy，可重试，协议线程不等待 UI 锁。

保存配置 仅保存已 Apply 的配置，未 Apply 时禁用。保存由独立工作线程执行，同目录临时文件完成序列化、解析回读校验、刷新后原子替换启动配置；保留角色、版本、数组、配置 faults/events 等完整字段，不保存手动临时注入。写入或校验失败保持原文件，错误可见；原子替换后的目录刷新失败会报告持久化错误，不能保证掉电后的内容。没有文件来源时不提供保存。界面显示已应用/已保存修订号及保存结果。

每轮开始通过工作线程输出 SESSION_CONFIG_BEGIN、带会话/修订号的 SESSION_CONFIG 片段及 SESSION_CONFIG_END，文件日志中可以还原当轮有效配置；不会阻塞 BMS 握手等待文件 I/O。UI 关闭时沿用原启动快照记录。

## 注入及日志隔离

手动规则优先于配置规则，配置规则保持原有声明顺序；命中日志包含 source=manual/config、规则编号及修改内容。取消或替换手动规则会移除其尚未派发的延迟任务，不清除配置规则任务，已经发送的帧不可撤回。本轮结束后临时规则清理，下一轮默认关闭；Idle 中重新预置的规则仅作用于后续新会话。

UI 日志缓存预算为 256 KiB，使用 224 条、每条最多 1152 字节的固定记录槽，展示淘汰/争用跳过的数量；控件显示文本另有 32 KiB 上限，移除最旧完整行。DETAIL 配置片段仍仅进入文件证据。暂停、筛选、清空及缓存淘汰不改变文件输出；file_log=false 时仍可查看屏幕日志。文件日志和 candump 保持原配置及最近三次进程启动的保留策略，不在 UI 中运行期重开文件。

## 线程与验证

协议线程独占引擎/TP/注入器；UI 线程独占 LVGL；保存及会话证据由独立工作线程处理，EasyLogger 继续异步输出。UI/保存线程使用 Linux 普通调度策略。快照界面按 100 ms 更新，显示任务约 5 ms 推进一次 LVGL；CAN 协议周期由原协议线程管理。

```bash
# 无 UI 完整回归（需要已准备 vcan0）
./scripts/verify_simulator.sh --prepare-vcan

# UI 完整回归、可选 ARM UI 构建
./scripts/verify_ui.sh --prepare-vcan
./scripts/verify_ui.sh --arm
```

sim_control 验证参数、保存往返、队列和注入任务归属；control_concurrency 验证真实线程下 2000 个请求及结果顺序。sim_ui 使用 LVGL 内存显示和指针输入覆盖两版双角色、多轮、停止、参数 Apply、注入取消、暂停恢复和失败轨迹，并输出 PPM 图像。

ui_vcan 运行正式入口、UI 线程及实际 SocketCAN 的两个子进程，仅用测试专用内存显示替换物理屏。界面按钮触发两轮，检查有效配置证据、真实 DT 间隔及 BCL/CCS 周期，不放宽原有时序判据。该替换只存在于测试可执行文件，不加入正式程序的 config。

以上软件测试不替代真实显示/触摸、旋转校准和实物桩/BMS 联调；没有设备时相应项目保持 SKIP。


## Web 屏幕镜像

含 UI 的同一个可执行文件可以通过 `ui.backend` 选择 `fbdev`（默认）或 `web`，两者互斥。Web 模式在内存中运行同一套中文 LVGL 界面，不需要实体屏幕、framebuffer 或触摸设备；UI 关闭时仍使用原来的无 UI 启动方式。

```json
"ui": {
  "enabled": true,
  "backend": "web",
  "web": {
    "listen": "0.0.0.0",
    "port": 8080,
    "vnc_port": 5900,
    "width": 800,
    "height": 480,
    "fps": 10
  }
}
```

完整示例为 `config/charger_web.json` 和 `config/bms_web.json`，都使用 manual 模式。启动桩端后，电脑浏览器打开 `http://板子IP:8080/`，点击“充电控制 → 开始充电”。BMS 默认示例网页端口为 8081、VNC/WebSocket 端口为 5901，等待对端合法 CHM 自动开始。

| 配置 | 默认值及范围 |
|---|---|
| ui.backend | fbdev；只允许 fbdev/web |
| ui.web.listen | 0.0.0.0；IPv4 地址；可指定 127.0.0.1 仅本机访问 |
| ui.web.port | 8080；1～65535，网页 HTTP 端口 |
| ui.web.vnc_port | 5900；1～65535，VNC/WebSocket 端口；不得与网页端口相同 |
| ui.web.width / height | 800 / 480；宽 480～1920，高 272～1080，单位 px |
| ui.web.fps | 10；1～30，内存画面交付网络线程的频率上限，不保证实际刷新率 |

`ui.rotation` 在 Web 模式必须为 0；浏览器按比例缩放固定画布，不改变板端虚拟分辨率。物理屏幕仍读取系统参数，Web 尺寸不影响 fbdev。修改后端、监听端口或虚拟尺寸需要重启，保存配置和会话配置快照包含全部新增字段。

网页与 WebSocket 使用两个 TCP 端口，电脑需要同时能访问它们。WSL 测试中若 localhost 网页可打开而画面不能连接，可使用 WSL 实际 IP 访问；本次环境存在网页端口转发正常、VNC 端口未转发的情况。SSH 使用独立连接，不占用这里的端口。

目前支持单个客户端、鼠标/触摸点击和拖动、自动及手动重新连接；第二个客户端被拒绝，当前客户端继续使用。断开时取消未完成的触摸，避免按住“开始”断网后误启动；协议继续运行，重连获取当前完整画面。文字编辑使用 LVGL 屏幕键盘。首版是 HTTP + WS，无认证和 TLS，不包含剪贴板、文件传输、动态改分辨率或多用户协作功能。

网页及 noVNC 模块内嵌在可执行文件中，板端只需程序与配置，不需要部署网页目录、Python、Node.js 或下载 CDN。构建时需要 Python 3 标准库生成资源数组。LibVNCServer 静态链接，无新增动态 VNC 库；原有 libc 等工具链运行库要求不变。可选 candump 仍需板端安装对应工具。

网络线程独占 VNC 状态，UI 线程独占 LVGL；通过两块全尺寸 32-bit 缓冲交换脏区域，加一个 64 行绘制缓冲。800×480 时这三块约 3.13 MiB，此外还有 LVGL、网络编码及程序资源开销；不是整进程内存上限。发送慢时保留最新画面，输入队列有界，断线或队列溢出会取消触摸。真实 i.MX6ULL 的资源占用和操作延迟需上板测量。
