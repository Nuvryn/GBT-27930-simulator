# LVGL UI 开发计划

状态：待实施。本文记录已确认的首版范围及实施顺序，不表示 UI 已接入或已通过测试。

## 目标与边界

- 使用 LVGL **v9.6.0** 固定源码，记录标签、完整提交、许可证和校验值；不跟随 master，不混用 8.x 示例及配置。
- 首先实现 ARM Linux 本机触屏 UI；每个进程仍模拟一个角色。Zephyr 仅保留平台契约及无 UI 骨架编译，不在本轮实现真实显示或触摸。
- 首版包含运行主页及充电流程图、参数设置、充电控制、手动错误注入、日志与设置五个页面。
- 不加入报文解析详情、趋势曲线、参数方案管理、一键异常预设、结果卡片、操作时间线、远程网页或命令 shell。
- 硬件操作仍只记录模拟动作；测量、自检、准备及预充条件来自配置或事件，UI 不直接操作充电硬件。
- 继续使用已有 cJSON、EasyLogger、Open-SAE-J1939 和 OSAL。显示、输入优先使用 LVGL 官方后端；如需增加 SDL、tslib、libinput 等依赖，先说明用途和适配成本，再征得用户同意。

## 页面与交互

| 页面 | 首版内容 | 主要限制 |
|---|---|---|
| 运行主页 | 角色、版本、CAN 接口、阶段、会话时间、主要电压/电流/SOC 及充电流程图 | 本端模拟值、对端报文值分别标明；未接收、失效或过期值不得当作当前有效值显示 |
| 参数设置 | 本角色可配置的标量充电字段，按报文分组；数字键盘、单位、范围、分辨率和错误提示 | 使用现有字段注册表及校验规则；单体数组、VIN 等复杂配置继续由 JSON 提供，不做首版编辑器 |
| 充电控制 | 桩端开始、双方停止、当前控制请求状态 | BMS 等待合法对端 CHM，不设置强制发送 BHM 的开始按钮；停止由协议引擎生成 CST/BST |
| 错误注入 | 阶段、报文、收发方向、动作、次数/持续时间、启用/取消、命中计数 | 覆盖丢弃、延迟、重复、字节修改、长度和标识符修改；TP 序号异常通过 TP_DT 序号字节修改表达 |
| 日志与设置 | 实时日志、滚动、暂停显示、清空显示、标签/文本筛选；版本、编译日期、配置来源、文件日志及抓包状态 | 暂停/清空只影响界面；首版不在运行中切换角色、版本、CAN 或重开日志/抓包资源 |

首版默认英文界面和内置英文字体，文档使用中文；不新增中文字体资产。页面以 800×480 为布局设计基准，使用弹性布局及滚动容纳内容，目标屏幕确认后验收实际分辨率，不能以开发尺寸替代板端验证。

### 充电流程图

正常路径示意：

```text
Idle → Handshake → Identification → Configuration → Ready
                                                   ↓
Idle ← Completed ← Statistics ← Stopping ← Charging
```

- 已完成、当前、未进入、异常四类样式同时使用文字/图标区分，不仅依靠颜色。
- 直接消费协议状态及状态事件，显示当前阶段持续时间、正在等待的报文或条件；不得根据日志字符串猜测状态，也不得使用固定动画推进流程。
- 区分“收到 BRO/CRO 就绪报文”等协议条件和模拟自检/预充条件；并行等待条件应全部列出，不能用单个“等待中”掩盖原因。
- 正常主动结束仍经过实际 Stopping/Statistics；异常按引擎实际进入的 Recovery/Done 路径显示，保留出错阶段、原因及相关报文。
- 2023 暂停/恢复若属于充电阶段内部状态，作为 Charging 节点的子状态展示，不凭空增设状态机迁移；重新进入同一阶段以实际事件重新计时。
- 回到 Idle 后保留上轮流程的最终样式和结果文字，同时明确当前已待机；下一轮开始时清除上轮轨迹。只保存最近一轮，不增加历史浏览页面。

## 配置、会话与线程设计

### 可选构建和运行

- 新增 CMake `SIM_UI`，默认 OFF。OFF 不编译、链接 LVGL，也不要求安装图形依赖；ON 为 Linux 构建界面。Zephyr 本轮只检查 OFF，要求 ON 时给出明确不支持提示。
- JSON 新增 `ui` 对象，最小字段为 `enabled`、`framebuffer`、`input_device`；省略 ui 等价于 enabled=false。设备路径非空且有长度上限，具体长度与现有路径字段一致。
- Linux 板端优先采用官方 fbdev + evdev：framebuffer 默认 `/dev/fb0`，触摸 input_device 在启用 UI 时必须明确配置，避免默认 event0 指向错误设备。显示尺寸及格式以设备查询结果为准。
- enabled=true 要求 SIM_UI=ON 且 start_mode=manual；配置不满足或显示/输入初始化失败时返回非零，不静默退回无屏模式。enabled=false 保留现有 manual Enter 和 auto 单次行为，不打开显示及触摸设备。
- UI 启用时，桩端开始操作只来自按钮，不再读取标准输入，防止无终端部署时 EOF 使进程退出；保留 SIGINT/SIGTERM 的会话中止与退出语义。

### 参数与保存

- 启动配置 → 待机可编辑配置 → 本轮不可变参数快照。UI 中的电压、电流按 V/A 显示，提交时准确转换为现有整数物理单位；禁止浮点舍入后绕过分辨率校验。
- 待机点击 Apply 后，由协议线程完成整体校验并替换下一轮参数；无效输入或会话已启动时拒绝替换并反馈原因。充电中参数编辑锁定，运行期改变报文内容统一通过错误注入完成。
- BMS 在收到 CHM 前使用最近一次已确认 Apply 的参数；尚未提交的文本不影响会话。协议线程先处理控制请求，再处理 CAN 接收，确定 Apply 与开始事件的顺序。
- 每轮开始记录实际使用的参数修订号和完整有效配置证据。较大的序列化、文件输出放在工作线程处理；会话开始前复制固定数据，BMS 握手不得等待日志文件 I/O。
- Save configuration 只在明确点击时保存已经 Apply 的参数，写回启动配置路径；UI 显示未保存状态。保存不隐含 Apply；未提交编辑时提示先 Apply。
- 保存使用 cJSON 和平台文件后端：同目录临时文件、校验及刷新后原子替换。失败保留原文件和当前内存参数，不影响正在进行的协议调度；错误在 UI 和日志中可见。
- 没有可写文件来源时禁用保存并说明原因。临时手动注入不写入 config，配置原有的 faults/events 和其他配置项必须保留；保存后配置能由正式解析器重新加载。

### 控制与数据交换

- 协议线程独占引擎、TP 和注入器；UI 线程独占全部 LVGL 对象和调用。沿用 EasyLogger 输出线程，文件保存任务放在独立工作线程，禁止在协议循环执行文件 I/O 或绘制。
- 新增平台无关的控制命令接口，包含请求编号及完成反馈：开始、停止、应用下一轮参数、启用/取消手动注入。命令数据按值复制或有明确所有权，不能引用 UI 控件内部缓冲。
- 控制命令采用有界队列，满时明确反馈 Busy，不阻塞协议循环、不静默丢弃；停止请求使用独立的合并标记，避免被普通命令挤占。重复开始、过期会话编号及非法阶段操作明确拒绝。
- 新增只读运行快照：会话编号、参数修订号、阶段及进入时间、等待条件、异常阶段/原因、主要本端/对端值与有效性、注入状态/计数和最近一轮结果。
- 快照通过短时同步复制，锁内不执行 LVGL、编码或 I/O；界面按 100 ms 周期更新。另传递有界状态迁移记录，避免刷新间隔内的短阶段被漏掉；记录溢出显示历史缺口，当前状态仍以快照为准。
- 手动注入与配置注入独立管理，手动规则优先，配置规则保持原顺序；命中日志标明来源及规则编号。修改或启停只由协议线程执行。
- 取消手动注入时移除该规则尚未派发的延迟/重复任务，已经发送的帧无法撤回；不得清除配置规则的任务。结束后清理手动规则及其计数，下一轮不自动继承，界面保持明确的未启用状态。
- 日志界面使用固定容量 256 KiB 的内存环形缓存，按完整记录保留最新内容，单条上限复用现有日志上限；淘汰旧记录时显示数量。输出线程或日志分流接口只复制文本，不回调 LVGL。
- UI 默认展示普通运行日志，DETAIL 启动配置片段仍只用于文件证据。关闭文件日志时仍可看屏幕日志；屏幕缓存淘汰不改变文件输出及其错误判据。

### 模块接口调整

| 模块 | 计划新增或调整的契约 |
|---|---|
| 配置 | ui 对象解析/有效配置输出；复用物理字段校验；保存完整配置的序列化入口 |
| 会话与引擎 | 待机替换参数、只读快照、结构化阶段/等待/异常事件；保留现有 start/stop/receive/tick 语义 |
| 注入器 | 带规则编号的手动规则管理、计数查询及按规则取消待派发任务 |
| 控制桥接 | 有界请求、请求结果、快照及迁移记录传递，不暴露 LVGL 类型给协议核心 |
| 日志 | 有界 UI 日志读取接口，不以屏幕速度约束文件输出 |
| 平台支持 | 显示/触摸初始化与释放、配置文件原子保存；Linux 实现，Zephyr 仅不支持桩接口 |

平台实现由 CMake 选择，业务层不增加平台条件编译。UI 相关能力关闭时使用无 UI 实现，不要求在业务代码中散布 SIM_UI 宏。

## 实施顺序与验收

每步交付代码、配置示例、必要测试、中文说明和独立中文 commit；接口变化在提交正文记录 `INTERFACE:`。本计划文件的提交仅记录设计，不引入依赖或改变运行行为。

| 步骤 | 实施内容 | 验收标准 |
|---|---|---|
| 0. 环境与依赖确认 | 固定 LVGL 源码、许可和校验；确认板端 framebuffer、触摸设备、分辨率、像素格式、旋转及输入坐标范围 | 固定依赖可离线构建；记录板端设备清单；未知板端条件保持待验证，不阻塞平台无关接口开发 |
| 1. 控制与状态基础 | 命令/反馈、快照、状态迁移记录、待机 Apply；为 Enter 和 UI 复用同一会话控制入口 | 可控时间下验证状态、等待条件及多轮重置；无 LVGL 时既有行为不变 |
| 2. 可选 UI 与平台后端 | SIM_UI/ui 配置、LVGL 线程、官方 fbdev/evdev 接入、基本导航 | 无 UI 不链接 LVGL；有 UI 可显示并触摸；退出正确释放资源；初始化失败非零 |
| 3. 主页与流程图 | 两版双角色状态映射、持续时间、等待条件、异常路径、上轮轨迹保留 | 图示与结构化引擎事件一致；快速阶段、暂停/恢复、超时、重连及回到待机均正确呈现 |
| 4. 充电控制 | 开始/停止按钮、请求反馈、双角色重复会话 | 桩端按钮触发 CHM，BMS 被动启动；正常或异常结束后待机，无需退出进程 |
| 5. 参数编辑与保存 | 数字输入/校验、Apply、Save、修订号和本轮配置证据 | 两轮使用不同参数；运行中不能改快照；保存后重启可恢复参数，保存失败不丢原配置 |
| 6. 手动错误注入 | 规则编辑、启停、命中反馈、与配置规则的优先级及结束清理 | 各注入动作可由 UI 制造；取消后不再影响后续帧；错误长度/TP 序号仍由现有边界处理，不能越界 |
| 7. 日志与设置 | 有界缓存、滚动/暂停/清空/筛选、构建及资源状态 | 长时间输出内存稳定；暂停屏幕不阻塞协议及文件线程；关闭文件保存仍可查看实时日志 |
| 8. 综合回归与板端联调 | UI 开关构建矩阵、vcan 双角色、真实时间性能和板端触屏测试 | 下述测试通过并保存证据；无板/无真实对端项目报告 SKIP；不将交叉编译当作运行验证 |

首个里程碑：**可选 UI 成功启动，主页流程图与协议状态一致，桩端按钮开始/停止及 BMS 被动启动可连续运行两轮；无 UI 回归通过。** 参数保存、完整注入面板和日志页作为后续里程碑交付，不以静态页面截图宣称功能完成。

## 测试与交付清单

- **接口测试**：请求队列满、重复开始、参数校验/单位换算、参数提交与 CHM 到达顺序、停止优先处理、快照一致性、快速阶段及事件溢出提示、失败会话销毁后保留轨迹。
- **流程图测试**：2015/2023 × charger/BMS 的正常结束、双方主动停止、各阶段超时、异常恢复、2023 暂停/恢复，以及 Idle 不运行握手计时；期望值来自协议规则及结构化事件，不能只验证控件与自身缓存一致。
- **注入测试**：各动作启用、命中、取消，配置/手动冲突，未派发延迟任务的精确取消及下一轮不残留；状态显示以协议线程确认结果为准。
- **配置测试**：ui 省略/关闭/启用、无 UI 构建却请求启用、auto 与 UI 冲突、非法路径及无权限；保存失败不破坏原文件；全部配置项往返加载不丢失，临时注入不持久化。
- **日志与线程测试**：持续高流量、暂停/恢复/筛选/清空、缓存环绕和淘汰统计；文件关闭与写入失败分别验证；ASan/UBSan 检查资源生命周期，针对共享状态补充并发检查。
- **软件对跑**：保持现有 17 项 CTest 和 29 个自动场景基线，新增用例独立登记；经控制入口驱动两版多轮充电、修改下一轮参数及运行期注入。无图形环境使用 LVGL 内存显示缓冲进行离屏测试，不默认增加 SDL。
- **真实时间**：UI 刷新、滚动和注入操作同时进行时，复核 DT 最小间隔、BCL/CCS 周期、CAN 环及日志丢失判据；沿用现有真实时间容差，不为 UI 放宽协议测试判据。
- **构建矩阵**：Linux/ARM Linux 的 SIM_UI=OFF/ON，Zephyr 的 OFF 骨架，固定依赖检查及所有构建的 compile_commands.json；本次修改的自有 C/H 运行 clang-format。
- **设备验收**：目标屏触摸、旋转、输入焦点、键盘遮挡、路径权限及退出；模拟桩对真实 BMS、模拟 BMS 对真实桩仍需真实设备。无环境明确 SKIP。
- **最终交付**：源码与固定依赖、UI/无 UI 配置示例、平台接入说明、操作说明、测试清单及证据；板端保持可执行文件与配置部署，启用 candump 时额外部署该系统工具。

尚需在步骤 0 记录的板端信息：型号/架构、内核和 libc、显示接口及设备路径、分辨率/像素格式、触摸设备与坐标映射。本文的英文界面、800×480 设计基准及 fbdev/evdev 为首版默认方案；若目标板仅提供 DRM 等其他后端，应在接入前更新计划及依赖评估，不直接假定 fbdev 可用。
