# DEVIATIONS — backends/hal/linux

All files under `backends/hal/linux/` are copied byte-for-byte from the upstream
framework's `backends/hal/linux/` directory. The deviations listed
below are the **only** intentional differences from the upstream framework
source. Nothing else was changed (no field mapping, error-code, or degradation
semantics were altered).

| # | File | Line | Change | Reason | Upstream recommendation | Date |
|---|------|------|--------|--------|-------------------------|------|
| 1 | `backends/hal/linux/hal_i2c.c` | 32 (directly after the existing `#include <linux/i2c-dev.h>` at line 31) | Added `#include <linux/i2c.h>` | Framework issue I9: on real Linux 5.x kernels, `<linux/i2c-dev.h>` does not define `struct i2c_msg` (the type used by `hal_i2c_transfer` via `struct i2c_rdwr_ioctl_data`). The header only came in transitively from `<linux/i2c.h>`, which is not guaranteed to be pulled in. | Keep both includes; `struct i2c_msg` is defined in `<linux/i2c.h>` and is required for any build that actually compiles the translation unit. | 2026-09-17 |
| 2 | `backends/hal/linux/hal_flash.c` | 32 (the `#include` line) | Changed `#include <linux/mtd/mtd-user.h>` to `#include <mtd/mtd-user.h>` | Compile-only gap revealed by the WSL gate on Ubuntu 22.04: the path `<linux/mtd/mtd-user.h>` does not exist in the Ubuntu `linux-libc-dev` 5.15 package set; the MTD userspace header is installed at `<mtd/mtd-user.h>` (`/usr/include/mtd/mtd-user.h`). Pure include-path fix; no semantic change. | Track the header location per-distro; Debian/Ubuntu ship MTD user-space headers under `/usr/include/mtd/` while some other distros expose `linux/mtd/`. Guard with a feature probe if cross-distro portability is required. | 2026-09-17 |
| 3 | `backends/hal/linux/hal_uart.c` | 21 (directly after the existing `#define _POSIX_C_SOURCE 200809L` at line 20) | Added `#define _DEFAULT_SOURCE` with comment `/* CRTSCTS is a __USE_MISC-only macro */` | Compile-only gap revealed by the WSL gate under glibc on Ubuntu 22.04: with `_POSIX_C_SOURCE 200809L` defined, glibc guards `CRTSCTS` behind `__USE_MISC` (see `/usr/include/x86_64-linux-gnu/bits/termios-baud.h`), so `hal_uart_init()` could not compile (`CRTSCTS undeclared`, line 177/179). Defining `_DEFAULT_SOURCE` alongside `_POSIX_C_SOURCE` restores the default feature set that exposes `CRTSCTS` while keeping strict POSIX functions available. Pure compile-fix; no behavioural change. | Keep `_DEFAULT_SOURCE` in production too if a strict `-std=c11 -pedantic` build is ever wanted; alternatively `#define _GNU_SOURCE` would also expose it but unlocks a broader surface than needed. | 2026-09-17 |
| 4 | `backends/hal/linux/hal_can.c` | 60 | `HAL_LINUX_CAN_POLL_TIMEOUT_MS` `500` -> `25` (plus `_Static_assert(... <= 50)`) | **Behavioural fix, not compile-only.** A synchronous `hal_can_send(..., done_cb=NULL)` waits at most the caller's timeout (the project adapter passes `CAN_BUS_TX_TIMEOUT_MS` = 100 ms), while the worker evaluates a deferred-TX deadline only at the top of its poll loop. With a 500 ms cadence the waiter could time out, read a stale `tx.last_status` (usually 0) and report success while the frame was still pending; the next frame then got `-EAGAIN` and was dropped — breaking `can_bus.h`'s documented "one frame completes before the next / never ahead of the hardware" guarantee (it held only on vcan). 25 ms makes the worker observe the deadline well before the 100 ms wait expires. Cost: 40 wake-ups/s while an RX filter is registered; the idle worker still self-exits. | Upstream: derive the poll cadence from the caller's timeout (e.g. `timeout/4`, clamped) or make the sync path re-check `tx.pending` / recompute the remaining time so the ordering guarantee holds for any caller-supplied timeout. | 2026-09-17 |
